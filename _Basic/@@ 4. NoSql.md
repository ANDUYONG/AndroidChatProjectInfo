## Gemini
> NoSQL은 님의 말씀대로 분산형 데이터베이스이며, 데이터 비정규화를 지향하는 것이 큰 특징입니다. NoSQL의 핵심 장점과 사용처를 더 자세히 살펴보겠습니다.

	데이터 형식의 유연성: NoSQL은 고정된 스키마가 없어 님의 말씀처럼 다양한 형태의 데이터를 자유롭게 저장할 수 있습니다. 대표적인 예시인 MongoDB는 JSON 형태의 문서로 데이터를 저장하며, 이는 데이터 구조가 자주 바뀌거나 정형화되지 않은 데이터를 다룰 때 매우 유용합니다.

	확장성: NoSQL은 수평적 확장이 용이합니다. 즉, 서버를 여러 대 추가하여 성능을 쉽게 확장할 수 있다는 의미입니다. 이는 대규모 데이터를 다룰 때 매우 중요한 장점입니다. 님의 말씀과 달리, NoSQL은 대규모 데이터를 다루는 것에 훨씬 더 유리하며, 특히 실시간으로 많은 양의 데이터를 처리해야 하는 서비스에 적합합니다.

	비용 효율성: NoSQL은 초기 설계 비용이 상대적으로 낮고, 유연한 구조 덕분에 개발 속도를 높일 수 있어 전체적인 서비스 개발 비용을 절감하는 데 도움이 됩니다.


#### 수평적 확장 vs 수직적 확장

먼저 확장 방식에 대해 이해하는 것이 중요합니다.

	수직적 확장(Vertical Scaling): 서버의 성능을 높여서(CPU, RAM, 디스크 등) 확장하는 방식입니다. 마치 건물의 층수를 높이는 것과 같습니다. 이 방식은 한계가 명확하고 비용이 많이 듭니다.
	
	수평적 확장(Horizontal Scaling): 서버를 여러 대 추가하여 확장하는 방식입니다. 건물을 옆으로 늘려가는 것과 같습니다. NoSQL은 이 방식에 최적화되어 있습니다.
	
	NoSQL이 수평적 확장에 유리한 이유
	NoSQL은 기본적으로 데이터가 여러 서버에 분산 저장되도록 설계되었습니다. 이 덕분에 대규모 데이터를 다룰 때 다음과 같은 장점을 가집니다.
	
	데이터 분산: NoSQL은 데이터를 여러 대의 서버(노드)에 나누어 저장합니다. 이를 **샤딩(Sharding)**이라고 합니다. 예를 들어, 100만 명의 사용자 데이터를 10대의 서버에 10만 명씩 나누어 저장할 수 있습니다.
	
	부하 분산: 데이터가 분산되면서, 데이터베이스에 가해지는 요청 부하도 분산됩니다. 특정 서버 한 대에 모든 요청이 집중되지 않고, 여러 서버가 요청을 나누어 처리하므로 전체적인 성능이 향상됩니다.
	
	유연한 확장: 만약 사용자가 1000만 명으로 늘어나면, 서버를 90대 더 추가하면 됩니다. 관계형 데이터베이스(RDB)처럼 복잡한 설정을 변경하거나 전체 시스템을 재구성할 필요가 거의 없습니다.
	
	대규모 데이터 처리에 유리한 이유
	정리하자면, NoSQL은 대량의 데이터를 여러 서버에 분산시켜 처리하기 때문에 다음과 같은 경우에 특히 유리합니다.
	
	대용량 트래픽: 쇼핑몰, 소셜 미디어와 같이 수많은 사용자가 동시에 접속하여 데이터를 읽고 쓰는 환경
	
	실시간 데이터 처리: 사물 인터넷(IoT) 기기에서 실시간으로 쏟아지는 센서 데이터나 로그 데이터
